Entregable 4 — Aplicación de analítica y cierre del proyecto

Temas que cubre: Tema 5 completo (aplicación web de analítica, integración de visualizaciones y funcionalidades, desarrollo y presentación del proyecto práctico), integrando resultados de los entregables 1–3.

Propósito

Exponer el valor del análisis en una interfaz usable y cerrar el proyecto con documentación y presentación claras para una audiencia académica/profesional.

Qué debe incluir este entregable

  1. Aplicación interactiva (Streamlit recomendado)
    • Carga de datos limpios (CSV y/o lectura desde SQLite).
    • Filtros globales (departamento, ciudad u otros relevantes).
    • Panel de indicadores (KPIs): conteos, promedios, medianas, etc.
    • Al menos dos visualizaciones integradas en la app (preferible Plotly).
    • Sección de predicción usando el modelo del Entregable 3 (formulario de entrada + resultado interpretado).
    • Notas visibles sobre limitaciones de los datos o del modelo.
  2. Calidad de ingeniería mínima
    • requirements.txt con versiones razonables.
    • Estructura de carpetas ordenada.
    • Instrucciones de ejecución en el README raíz del proyecto.
  3. Documentación del proyecto
    • Problema y objetivo.
    • Datos y preparación (resumen del Entregable 1).
    • Principales hallazgos (resumen del Entregable 2).
    • Modelo elegido y métricas (resumen del Entregable 3).
    • Cómo usar la app.
    • Limitaciones y trabajo futuro.
  4. Presentación final
    • Exposición oral o video breve según indique el docente.
    • Demostración en vivo de la aplicación.
    • Respuesta a preguntas sobre decisiones técnicas.

Productos a entregar

  • Código de la app en app/ (por ejemplo app.py).
  • README completo del repositorio.
  • Enlace al repositorio GitHub (público o compartido con el docente).
  • Material de presentación (diapositivas o guion estructurado).
Integración real La app no es un ejercicio aislado: debe consumir datos limpios y el modelo ya validados. Si algo no está listo, documenta el faltante y ofrece un modo degradado explícito (por ejemplo estimación de respaldo).
